# 愛知・名古屋2026 アジアパラ｜自動更新ダッシュボード v3

## 最初にご確認ください

このZIPは「コード・表示画面・定期取得処理」が組み込まれた公開準備済みの一式です。ただし**まだインターネットで公開されておらず、データの自動取得も稼働していません**。ここに記載のGitHub設定を実施すると、ブラウザで開ける共有用HTTPS URLが発行され、公式ニュース・会場セッション情報の取得・保存・公開が自動化されます。

### 自動更新の時間・期間

- JST（日本時間）**毎日09:00から23:55までは5分おき**、**24:00に最終チェック**。
- 2026年10月16〜24日の期間中に取得します。16〜17日は一部競技が開会前から始まるため追加しています。
- GitHub Actionsの時刻指定はUTCです。実際の実行開始には数分以上の遅延・欠落が起こり得ます。5分ごとの実行を保証する専用リアルタイムインフラではありません。
- `workflow_dispatch` ボタンから、時間帯以外でも手動で1回実行できます。
- ブラウザが開いている間は**5分ごとに最新公開JSONを再読込**します。ブラウザを閉じていてもGitHub Actionsが更新します。

### 何が自動、何が手動？

| 機能 | 状態 |
|---|---|
| 大会公式ニュース | 自動取得。WordPress API → RSS → 公式記事一覧の順に試す。失敗は画面に表示。 |
| 競技セッションの日付・開始・終了予定時刻 | 公式会場ページ18か所を定期取得。変更前→変更後の比較あり。陸上競技場はWeb上のセッション表を機械的に読み取れず、参考表を残します。 |
| 金メダル関連ニュース | 日本勢＋金メダル／優勝の語句に合う記事を**未確認候補**として表示。誤検知あり。 |
| 金メダル結果の自動認定 | **未実装**。公式競技結果 https://pre.results.apg2026.org/ はJavaScriptのWebアプリで、検証済みの機械取得APIがありません。キーワードだけで選手名や獲得結果を推定しません。 |
| 金メダル速報用フィード・キャプション作成 | 確認担当者が個別公式結果URLを照合して登録した結果から生成。画像アドバイスと構成案付き。 |
| Instagramへの自動投稿 | 未実装。投稿前の権利チェックと承認が必要です。 |

公式結果の個別APIや正式なデータフィードへの接続方法が得られた場合、後から金メダルの自動認定を追加できます。現時点で「全自動で金メダル確定」とは表示しません。

## 公開URLを発行して自動化を稼働する手順（GitHub Pages）

**この作業にはGitHubアカウントが必要です**。現在のアカウントへの認証やGitHubリポジトリへのアップロード操作をこちらから完了できないため、以下は利用者側で行ってください。

1. ZIPを展開して、`index.html`、`data/`、`scripts/`、`tests/`、`requirements.txt`、`.github/`、`.nojekyll` が同じフォルダにあることを確認する。Macで `.github` が見えない場合は **Command + Shift + .** で隠しファイルを表示する。
2. [GitHub](https://github.com/new) で `asianpara-2026-live` などの**新しい公開（Public）リポジトリ**を作る。元ファイルをそのリポジトリのルートにアップロードし、**`.github/workflows/auto-sync.yml` も必ずアップロードする**。GitHub Desktopを使うとフォルダ構成を保ったままPublishできます。
3. GitHubリポジトリの **Settings → Pages → Build and deployment → Source を「GitHub Actions」**に設定する（`Deploy from a branch` ではなく `GitHub Actions`）。
4. **Settings → Actions → General → Workflow permissions** を確認し、`Read and write permissions` とPagesデプロイに必要な権限が許可されていることを確認する。組織アカウントの場合は管理者権限が必要になる場合があります。
5. **Actions → Asian Para 2026 official data sync and Pages deployment → Run workflow** を一度押す。初回の実行ログに取得失敗が表示される場合は、公式サイト側のブロックやフォーマット変更が原因です。**成功を装いません**。
6. 実行が終わると **Settings → Pages** にURLが表示されます。例：`https://（GitHubユーザー名）.github.io/asianpara-2026-live/`。このURLは**例であり、まだ作成済みの実URLではありません**。
7. 公開URLを開き、上部の「公式データ自動更新」が最新の時刻・取得成功／失敗／一部取得を表示することを確認します。

**重要：GitHub Pagesは公開サイトです。** このプロジェクトをPublicにすると、公式ページから取得した公開スナップショットも第三者に見えます。制作中の未公開原稿、選手写真、個人情報、投稿管理情報はGitHubにアップロードしないでください。投稿管理・承認済み結果の手入力内容は各端末の**ブラウザlocalStorage**に保存され、チーム全員で自動共有されません。共同編集には認証付きDBの追加開発が必要です。

## 最新データはどこに保存される？

`data/live.json` に以下を格納します。

- `generated_at_utc` ・・・ 最後に同期処理が動いた時刻（必ずしも取得成功を意味しません）
- `sources.news` ・・・ 公式ニュース取得の成否・方式・最後の成功時刻
- `sources.schedule` ・・・ 18会場の時刻表取得成否・エラー・最後の成功時刻
- `sources.results` ・・・ 未接続を明示
- `updates` ・・・ URL付きの公式ニュース（重複除去）
- `sessions` ・・・ 競技名・開催日・セッション開始／終了予定・原文URL
- `schedule_changes` ・・・ 変更時刻・旧値・新値・原文URL
- `gold_candidates` ・・・ **未検証**の金メダル関連ニュースのみ
- `verified_gold` ・・・ 自動確定禁止のため空配列。手動承認はブラウザ内に保存。

ソース取得に失敗した場合も、最後に取得できた記事や競技時刻のデータを保持し、取得失敗と時刻を記録します。大会公式スケジュールに変更があってもサイトに掲載されるまで検知できず、公式がPDFのみに掲載する詳細や個別対戦カードは自動取得できない場合があります。

## 運用上の確認

1. 投稿候補から当該結果の**個別公式発表・公式結果画面のURL**を開く。
2. 金メダル・日本代表・選手名・競技／種目・クラス・記録・獲得日時を確認してフォームに記録する。
3. エビデンスURLと照合担当者を登録する。未検証候補は直接投稿素材にはできない。
4. フィードのキャプションと「スポーツ記者視点・写真／構成アドバイス」を確認する。大会動画の**存在とリンク先が実際に確認できた場合だけ**動画へ誘導する。
5. 選手の肖像・写真・大会ロゴの使用権限を確認し、Instagramへ手動で投稿する。
